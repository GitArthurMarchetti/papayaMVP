# Automatic Sticker Proofing System (MVP)

## 0. Run:

**npm run dev**

## 1. Overview

This project is a Minimum Viable Product (MVP) for an automatic sticker proofing system built with Next.js and TypeScript. The application allows users to upload their own images, configure various sticker properties (such as cut type, shape, material, and size), and see a real-time preview of the final product with die-cut or kiss-cut lines.

The primary goal of this system is to provide an intuitive interface for customers to visualize their custom stickers, streamlining the design and approval process.

## 3. Core Features

* **Image Upload:** Users can upload PNG images to be used as sticker designs.
* **Multiple Design Management:** The interface supports uploading and switching between multiple designs in a single session.
* **Real-time Canvas Preview:** A dynamic canvas displays the selected design along with a generated cut line based on user configurations.
* **Sticker Configuration:**
    * **Product Type:** Choose between "Die Cut" and "Kiss Cut" stickers.
    * **Shape:** Select from "Contour," "Square," or "Circle" shapes for the cut line.
    * **Spacing:** Adjust inner (for Kiss Cut) and outer (for both) spacing around the design.
    * **Appearance:** Configure material (Vinyl, Holographic, Transparent) and finish (Glossy, Matte).
    * **Size & Quantity:** Set the dimensions (width, height) and the number of stickers to order.
* **Dynamic Annotations:** The preview canvas includes annotations for width and height, updating in real-time.

## 4. How It Works: A Deeper Dive

### 4.1. State Management (`useDesigns.ts`)

The entire application state is managed by a single custom hook: `useDesigns`. This hook centralizes all logic related to the designs, making the system predictable and easier to debug.

* **`designs`**: An array of `Design` objects. Each object contains its `id`, `name`, image `src` (as a blob URL), and its unique `config` object.
* **`activeIndex`**: A number that tracks which design is currently selected by the user for editing and previewing.
* **`activeDesign`**: A derived state that provides the full object of the currently active design.
* **`handleFileChange`**: Triggered when a user uploads an image. It creates a new `Design` object with a default configuration, adds it to the `designs` array, and sets it as the active design.
* **`handleDelete`**: Removes a design from the `designs` array and revokes its object URL to prevent memory leaks.
* **`handleConfigChange`**: This is a generic function that updates a specific property (e.g., `shape`, `outerGap`, `material`) of the `activeDesign`. It receives a `field` and a `value`, finds the active design in the array, and updates its configuration immutably.

### 4.2. Image Processing & Canvas Logic (`/lib` directory)

This is the core of the proofing system. The logic is split between two main files:

#### `imageProcessing.ts`

This file contains low-level functions that analyze the pixel data of an uploaded image to create a "mask" of the object.

1.  **`buildObjectMask`**: This function inspects an `ImageData` object. If the image has transparency, it creates a mask based on the alpha channel. If not, it assumes the background color is at the top-left corner and creates a mask by identifying all pixels that are different from this color (within a tolerance).
2.  **`findAllComponents` / `getLargestComponentMask`**: After creating a raw mask, these functions are used to identify distinct, separate "islands" of pixels. This is crucial for handling images with multiple disconnected parts. The system can be configured to either find the single largest component or all of them.
3.  **`chamferDistance`**: A key algorithm that calculates, for every pixel, its distance to the nearest pixel of the object mask. This distance field is what allows us to efficiently generate an outline (the cut line) at a specific `gap` from the original shape.

#### `canvas.ts`

This file uses the data from `imageProcessing.ts` to draw the final preview on the screen.

1.  **`generateAndDrawOutline`**: This is the main orchestrator function.
    * It takes the original image (`img`) and the active design's `config` as input.
    * It creates a temporary, higher-resolution working canvas (`workCanvas`) to perform the image processing accurately. This is done to achieve smoother contour lines (`FIXED_SMOOTHNESS`).
    * It calls `buildObjectMask` to get the shape of the sticker.
    * It calls `chamferDistance` on the mask.
    * It then iterates through the distance data. Any pixel whose distance falls within the desired range (e.g., between `gap` and `gap + lineWidth`) is colored in, creating the contour line.
    * Finally, it draws the original user image onto the main preview canvas and then overlays the generated contour line on top.
2.  **Handling Cut Types**:
    * **Die Cut**: Generates a single outline around the object(s) based on the selected `shape` (`Contour`, `Square`, `Circle`).
    * **Kiss Cut**: Generates individual "inner" contour lines for every component in the image (using `getAllComponentMasks`) and then draws a single "outer" Die Cut line around the bounding box of all components combined.

## 5. Component Breakdown

* **`app/page.tsx` (`StickerProofPage`)**: The root page component. It calls the `useDesigns` hook and passes the state and handler functions down to its children components (`DesignSidebar`, `PreviewCanvas`, `ConfigPanel`).

* **`DesignSidebar`**:
    * Displays thumbnails of all uploaded designs.
    * Allows the user to select a design to edit by clicking on it (`setActiveIndex`).
    * Contains the "Upload File" button which triggers the file input.
    * Shows a delete button on each design thumbnail.

* **`ConfigPanel`**:
    * The main container for all the settings. It's organized into sections: "Product & Shape," "Appearance," and "Size & Quantity."
    * It receives the `activeDesign` and the `handleConfigChange` function. Every interactive element within this panel (e.g., a button, a dropdown, an input field) calls `handleConfigChange` with the corresponding property name and new value. For example, clicking the "Matte" button calls `handleConfigChange('finish', 'Matte')`.

* **`PreviewCanvas`**:
    * The most critical UI component for the user.
    * It uses a `useEffect` hook that listens for changes to `activeDesign`.
    * When `activeDesign` changes (either a new design is selected or its configuration is modified), the effect runs:
        1.  It creates a new `Image` object from the design's `src`.
        2.  Once the image is loaded, it calls the `generateAndDrawOutline` function from `canvas.ts`, passing the image and its configuration.
        3.  This function takes care of clearing and redrawing the canvas with the updated preview.
    * It also renders the `SizeAnnotation` components, which display the width and height.
